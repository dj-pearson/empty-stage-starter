# USDA Generic Backbone Seed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seed `grocery_product_catalog` with roughly 1500-2000 generic foods from USDA, each carrying a category, an aisle and per-100g nutrition, from a checked-in script that can regenerate the seed.

**Architecture:** A Node script reads the two USDA CSV exports, filters them down to foods families actually eat, pivots the seven nutrients we store, assigns an aisle from a hand-editable category map, and writes a JSON seed file. A second script turns that JSON into a SQL migration. Both the JSON and the migration are checked in, so review sees the data and production gets it through the normal migration path.

**Tech Stack:** Node 20 (no new dependencies -- CSV parsing is hand-rolled against a known-quoted format), Postgres, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-06-shared-food-catalog-design.md`

**Story:** US-794 in `prd.json`.

## Global Constraints

- Additive only. The seed INSERTs rows; it alters no column and drops nothing.
- `grocery_product_catalog_name_uq` is UNIQUE on `name_normalized` alone. Two USDA foods that normalize to the same name are a collision the seed must resolve before emitting, not at INSERT time.
- Seeded rows are `kind='generic'`, `source='usda'`, `verification='verified'`, `source_ref` = the USDA `fdc_id`.
- A migration runs with `auth.uid()` null, which `gpc_guard_verification()` treats as a trusted context, so the seed may set `verification='verified'` directly. This is the seeding path US-793 opened; do not work around the trigger.
- Nutrition is per 100 g. USDA `food_nutrient.amount` is already per 100 g -- do not rescale.
- CHECK bounds: calories 0-900, each macro 0-100. A row outside them is dropped by the script with a reason, never clamped.
- Never `supabase db push` against production.
- ASCII only in generated SQL and JSON. USDA descriptions contain non-ASCII; transliterate or strip rather than emitting curly quotes into a SQL literal.
- `$DB_URL` below is the local Supabase connection string. Get it with
  `eval "$(npx supabase status -o env | grep ^DB_URL)"` rather than writing the
  literal into a file — `scripts/ci/check-committed-secrets.sh` matches the
  `user:password@host` shape and fails the build on it, correctly, even when the
  value is only the local dev default.

## Source data

Downloaded to a working directory the script takes as an argument. Not checked in.

- Foundation Foods: `https://fdc.nal.usda.gov/fdc-datasets/FoodData_Central_foundation_food_csv_2025-04-24.zip` (3.4 MB). `food.csv` holds 74176 rows of which only the 411 with `data_type = 'foundation_food'` are foods; the rest are sampling metadata.
- SR Legacy: `https://fdc.nal.usda.gov/fdc-datasets/FoodData_Central_sr_legacy_food_csv_2018-04.zip` (6.1 MB). `food.csv` holds 7793 rows, all `data_type = 'sr_legacy_food'`.

`food.csv` columns: `fdc_id, data_type, description, food_category_id, publication_date`.
`food_nutrient.csv` columns: `id, fdc_id, nutrient_id, amount, data_points, derivation_id, min, max, median, footnote, min_year_acquired`.
`food_category.csv` columns: `id, code, description`.

Nutrient ids to pivot:

| nutrient_id | meaning | target column | unit |
| --- | --- | --- | --- |
| 1008 | Energy | `calories_kcal_100` | kcal |
| 1003 | Protein | `protein_g_100` | g |
| 1005 | Carbohydrate, by difference | `carbs_g_100` | g |
| 1004 | Total lipid (fat) | `fat_g_100` | g |
| 1079 | Fiber, total dietary | `fiber_g_100` | g |
| 2000 | Sugars, Total | `sugar_g_100` | g |
| 1093 | Sodium, Na | `sodium_mg_100` | mg |

Note 1062 is Energy in kJ. Use 1008 only.

SR Legacy `food_category` ids, which the aisle map keys off:

`1` Dairy and Egg Products, `2` Spices and Herbs, `3` Baby Foods, `4` Fats and Oils, `5` Poultry Products, `6` Soups Sauces and Gravies, `7` Sausages and Luncheon Meats, `8` Breakfast Cereals, `9` Fruits and Fruit Juices, `10` Pork Products, `11` Vegetables and Vegetable Products, `12` Nut and Seed Products, `13` Beef Products, `14` Beverages, `15` Finfish and Shellfish Products, `16` Legumes and Legume Products, `17` Lamb Veal and Game Products, `18` Baked Products, `19` Sweets, `20` Cereal Grains and Pasta, `21` Fast Foods, `22` Meals Entrees and Side Dishes, `23` Snacks, `24` American Indian/Alaska Native Foods, `25` Restaurant Foods, `26` Branded Food Products Database, `27` Quality Control Materials, `28` Alcoholic Beverages.

### Task 1: The category-to-aisle map, as data

**Files:**
- Create: `scripts/seed/food-aisle-map.mjs`
- Test: `src/lib/foodAisleMap.test.ts`

**Interfaces:**
- Produces: `export const CATEGORY_AISLE` -- a `Record<string, {category: string, aisle: string}>` keyed by the USDA `food_category_id` as a string. Also `export const EXCLUDED_CATEGORIES` -- a `Set<string>` of ids the seed drops entirely.
- Consumed by Task 2's builder.

This file is the part of "known correct" only a person can supply, so it is a standalone, hand-editable table with one line per USDA category and no logic. AC 3 of the story says the aisle is derived from category as a first pass and then corrected by hand; this file is what gets corrected.

- [ ] **Step 1: Write the failing test**

```ts
import { describe, it, expect } from 'vitest';
import { CATEGORY_AISLE, EXCLUDED_CATEGORIES } from '../../scripts/seed/food-aisle-map.mjs';

/** The 28 USDA SR Legacy category ids. Every one is either mapped or excluded. */
const USDA_CATEGORY_IDS = Array.from({ length: 28 }, (_, i) => String(i + 1));

describe('USDA category to aisle map', () => {
  it('accounts for every USDA category, either mapped or excluded', () => {
    for (const id of USDA_CATEGORY_IDS) {
      const decided = Object.hasOwn(CATEGORY_AISLE, id) || EXCLUDED_CATEGORIES.has(id);
      expect(decided, `category ${id} is neither mapped nor excluded`).toBe(true);
    }
  });

  it('never both maps and excludes the same category', () => {
    for (const id of Object.keys(CATEGORY_AISLE)) {
      expect(EXCLUDED_CATEGORIES.has(id), `category ${id} is both mapped and excluded`).toBe(false);
    }
  });

  it('gives every mapped category a non-empty category and aisle', () => {
    for (const [id, v] of Object.entries(CATEGORY_AISLE)) {
      expect(v.category, `category ${id} has no category`).toBeTruthy();
      expect(v.aisle, `category ${id} has no aisle`).toBeTruthy();
    }
  });

  it('excludes the categories that are not family groceries', () => {
    // Restaurant Foods, Branded (a separate database), Quality Control
    // Materials (lab reference standards) and Alcoholic Beverages have no
    // place in a shared catalog a parent shops from.
    for (const id of ['25', '26', '27', '28']) {
      expect(EXCLUDED_CATEGORIES.has(id), `category ${id} should be excluded`).toBe(true);
    }
  });
});
```

### Task 2: The seed builder

**Files:**
- Create: `scripts/seed/build-food-seed.mjs`
- Create (generated, checked in): `supabase/seed/canonical_foods.json`
- Test: `src/lib/foodSeedBuilder.test.ts`

**Interfaces:**
- Consumes: `CATEGORY_AISLE`, `EXCLUDED_CATEGORIES` from Task 1.
- Produces: `export function buildSeed({foods, nutrients, categoryAisle, excluded})` returning `{rows, dropped}`. `rows` are objects shaped like a `grocery_product_catalog` insert; `dropped` is an array of `{fdc_id, description, reason}` so a filtering decision can be audited rather than guessed at.
- Also `export function normalizeName(description)` and `export function displayName(description)`, both pure and both tested directly.

Usage: `node scripts/seed/build-food-seed.mjs <path-to-unzipped-usda-dir> [--out supabase/seed/canonical_foods.json]`, where the directory contains both the Foundation and SR Legacy export folders.

- [ ] **Step 1: Write the failing test**

Test the pure functions and the filter with hand-built fixtures. Do NOT require the USDA download to run the suite.

```ts
import { describe, it, expect } from 'vitest';
import { buildSeed, normalizeName, displayName } from '../../scripts/seed/build-food-seed.mjs';

const CATEGORY_AISLE = { '9': { category: 'fruit', aisle: 'Produce' } };
const EXCLUDED = new Set(['26']);

/** Minimal shapes matching the USDA CSV columns we read. */
const foods = [
  { fdc_id: '1', data_type: 'sr_legacy_food', description: 'Lemons, raw, without peel', food_category_id: '9' },
  { fdc_id: '2', data_type: 'sr_legacy_food', description: 'Beef, chuck, arm pot roast, separable lean only, raw', food_category_id: '13' },
  { fdc_id: '3', data_type: 'sr_legacy_food', description: 'Cheerios', food_category_id: '26' },
  { fdc_id: '4', data_type: 'sub_sample_food', description: 'Apples, raw', food_category_id: '9' },
  { fdc_id: '5', data_type: 'sr_legacy_food', description: 'Lemons, raw', food_category_id: '9' },
];
const nutrients = [
  { fdc_id: '1', nutrient_id: '1008', amount: '29' },
  { fdc_id: '1', nutrient_id: '1003', amount: '1.1' },
  { fdc_id: '5', nutrient_id: '1008', amount: '29' },
];

describe('normalizeName', () => {
  it('lowercases and collapses to a stable key', () => {
    expect(normalizeName('Lemons, raw, without peel')).toBe(normalizeName('LEMONS, RAW, WITHOUT PEEL'));
  });
  it('strips characters a SQL literal should never carry', () => {
    expect(normalizeName('Creme fraiche')).toMatch(/^[a-z0-9 -]+$/);
  });
});

describe('displayName', () => {
  it('drops the trailing preparation clause', () => {
    expect(displayName('Lemons, raw, without peel')).toBe('Lemons');
  });
  it('keeps a clause that distinguishes the food', () => {
    expect(displayName('Beef, ground, 80% lean')).toBe('Beef, ground, 80% lean');
  });
  it('title-cases a shouted description', () => {
    expect(displayName('HUMMUS, CLASSIC')).toBe('Hummus, Classic');
  });
});

describe('buildSeed', () => {
  const { rows, dropped } = buildSeed({ foods, nutrients, categoryAisle: CATEGORY_AISLE, excluded: EXCLUDED });

  it('keeps only real food rows', () => {
    // fdc 4 is sub_sample_food, which is sampling metadata and not a food.
    expect(dropped.find(d => d.fdc_id === '4')?.reason).toMatch(/data_type/);
  });
  it('drops an excluded category', () => {
    expect(dropped.find(d => d.fdc_id === '3')?.reason).toMatch(/category/);
  });
  it('drops a lab-speak description', () => {
    expect(dropped.find(d => d.fdc_id === '2')?.reason).toMatch(/lab|separable/i);
  });
  it('drops a row with no calories rather than seeding a hole', () => {
    expect(rows.every(r => typeof r.calories_kcal_100 === 'number')).toBe(true);
  });
  it('resolves a name_normalized collision instead of emitting both', () => {
    const keys = rows.map(r => r.name_normalized);
    expect(new Set(keys).size).toBe(keys.length);
    expect(dropped.find(d => d.fdc_id === '5')?.reason).toMatch(/collision|duplicate/i);
  });
  it('stamps provenance on every row', () => {
    for (const r of rows) {
      expect(r.kind).toBe('generic');
      expect(r.source).toBe('usda');
      expect(r.verification).toBe('verified');
      expect(r.source_ref).toBeTruthy();
    }
  });
  it('drops a row whose nutrition is outside the CHECK bounds rather than clamping it', () => {
    const out = buildSeed({
      foods: [{ fdc_id: '9', data_type: 'sr_legacy_food', description: 'Impossible food', food_category_id: '9' }],
      nutrients: [{ fdc_id: '9', nutrient_id: '1008', amount: '1200' }],
      categoryAisle: CATEGORY_AISLE, excluded: EXCLUDED,
    });
    expect(out.rows).toHaveLength(0);
    expect(out.dropped[0].reason).toMatch(/bounds|range/i);
  });
});
```

- [ ] **Step 3: Write the builder**

The lab-speak filter is the judgement-heavy part. - [ ] **Step 1: Write the failing SQL test**

`supabase/tests/us794_usda_seed.test.sql`, in the same fail-loud style as `supabase/tests/us793_canonical_catalog.test.sql` -- every assertion is a `DO` block that `RAISE EXCEPTION`s on mismatch and `RAISE NOTICE`s on success. Read that file first and match it. Assertions:

2. Every one of them has a non-null `category`, a non-null `aisle`-equivalent column (use whichever column the catalog actually has -- read the table, do not assume) and a non-null `calories_kcal_100`.
3. Every one is `kind = 'generic'`, `verification = 'verified'`, and has a non-null `source_ref`.

5. `source_ref` is unique across seeded rows.
6. Re-running the migration body a second time inside the transaction inserts zero additional rows (idempotency).

End the file with `ROLLBACK;`.

- [ ] **Step 3: Write the migration generator and generate the migration**

`scripts/seed/seed-to-migration.mjs` reads the JSON and writes one `INSERT INTO public.grocery_product_catalog (...) VALUES ... ON CONFLICT (name_normalized) DO NOTHING;` in batches of 500 rows.

`DO NOTHING`, not `DO UPDATE`: it satisfies the story's "does not overwrite rows an operator has since edited" directly and makes re-running trivially idempotent. A correction to seeded data ships as a new migration, which is the right shape for versioned data.

Escape single quotes by doubling. Emit ASCII only.
